# buns3 — project context

Lightweight S3-like object storage server. **Learning project**: Sebastian writes the code; Claude advises, reviews, and runs verification probes — don't write feature code unless explicitly asked. Claude SHOULD run curl probes / scripts / tsc to verify claims empirically ("trust the wire, not the docs" is the house method).

## Philosophy

- **Not an S3 clone.** S3 is a reference point, not a requirement. Simplicity wins. S3 ideas are kept only when independently good (bucket name rules, refuse deleting non-empty buckets, 403-without-existence-check outside key scope).
- Decisions are made deliberately and documented; "decide on purpose, write it down" over accidental behavior.
- Empiricism: every claim gets verified with a probe (curl, scratch scripts, reading node_modules types/dist as ground truth). Betas lie; types lie; the wire decides.

## Stack (deliberately bleeding-edge; pin exact versions)

- **Bun** runtime. `bun run dev` = `bun --watch ./src`. Bun does NOT type-check: run `bun x tsc --noEmit` explicitly (worth doing before believing any refactor).
- **Bun workspace** (`packages/*`, **hoisted linker — pinned in `bunfig.toml [install]`**) with a `dev` catalog in root `package.json` (`workspaces.catalogs.dev`): `@types/bun` and `typescript` are pinned THERE, referenced as `"catalog:dev"` everywhere — one edit moves every workspace. **Why hoisted (RE-decided 2026-09-03, isolated was the first choice):** the isolated linker builds `node_modules` out of Windows junctions, and **Redirection Guard makes SSH-spawned processes refuse to traverse user-created junctions** ("icke betrodd monteringspunkt" / untrusted mount point) — `bun test` and the TS server failed with "Cannot find module '@prisma/orm-sqlite/runtime'" from every Remote-SSH terminal while passing on the desktop; `Test-Path` on the junction target was True, only the link was untraversable. Hoisted = plain directories, works in every session type; running installs elevated ("trusted" junctions) was rejected as a trap. The SDK's no-Bun-globals guard is `"types": []` in its tsconfig (with `@types/bun` installed for tests via `tsconfig.test.json`) — a stray `Bun.*` in `src/` is a compile error, not a portability bug shipped to npm; the linker layout is irrelevant to it. **Never switch linkers on a live `node_modules`** — it leaves a half-migrated tree (`.old_modules-*` backup, "Cannot find name 'process'"). Fix is `rm -rf node_modules && bun install`, not config. Root `tsconfig.json` excludes `packages/` — each workspace typechecks itself (the SDK's DOM lib vs the server's Bun types).
- **Elysia 2.0 beta** (pinned). Plugins must be their `2.0.0-*` releases — npm `latest` tags still point at 1.4-era builds whose peer ranges falsely allow 2.0. Check dist-tags (`next`) before adding any plugin.
- **Prisma Next (Prisma 8 RC)** — contract-first: `src/modules/prisma/contract.prisma` → `bunx prisma contract emit` → migration plan → apply. READ migration plans before applying (no rename detection; renames render as destructive drop+add). CLI: `--json` gives full error envelopes where `-v` shows nothing.
  - `migration plan` never chains from the newest migration on disk — origin is `--from`, else the `db` ref (`migrations/app/refs/db.json`, committed), else empty (refused). Apply with `db migrate --advance-ref db` or the ref lags and the next plan needs `--from` again — **locally only**: the flag writes back into the source tree, so the container runs bare `db migrate` (see deployment).
  - **No `@default(now())` on DateTime** — it renders `datetime('now')`, whose naive string the `sqlite/datetime@1` codec parses as *local* time on read (tz skew; upstream bug candidate). All timestamps are stamped from JS (`new Date()` round-trips ISO-Z on every lane). DB defaults are allowed only when they can solely fail closed (`publicRead 0`) — and the write path still stamps explicitly; the default is the migration backstop.
  - **ORM gotchas (orm-sqlite rc.8, all probed)**: no terminal `.count()` on collections — use `.aggregate((a) => ({ n: a.count() }))`; bare `.count` resolves to the include-reducer and throws ORM.INCLUDE_INVALID. Collection-form `.include("rel")` type-collapses rows to `{[x:string]: unknown}[]` (runtime probably fine, types broken) — reducer form (`(o) => o.count()`) types correctly; query the relation's own collection directly instead. Chained `.where()` AND-composes and keeps the collection generic (safe to `let`-reassign for conditional filters). Bulk delete = `.select(...).deleteAll()` — RETURNING-style, hands back the rows actually deleted (use as ground truth over any pre-select). `.in([...])` with 1000+ bound params is fine — this build carries SQLite's modern 32766 variable limit (probed), not the historical 999.
- **arktype** for validation (Standard Schema). `string.integer` VALIDATES a string (stays string); `string.integer.parse` MORPHS to number — `.to("number...")` on the unparsed form is an unsatisfiable string∩number intersection that throws at module load (= server down, schemas build at import). **`@elysia/openapi` is locally patched** (`patches/`) — its dist/gen had broken relative typebox imports; patch reapplies on install via `bun patch`.

## Architecture

- `src/lib/` — framework-free (no Elysia imports; enforced by comment in error.ts): error codes, `Buns3Error`/`Buns3ValidationError`, `unwrap`, key/encoding helpers (`strictEncode`, `uriEncodedKey`, `keyToFilename`).
- `src/modules/storage/` — fileStorage + bucketStorage. **Results-as-values, never throws.** Flat blob layout: `data/<bucket>/<uuid>`, metadata in SQLite; keys are opaque strings that never touch the filesystem. Write-order invariants: blob durable before pointer commit; pointer dropped before blob unlink; temp files in `data/.tmp` then rename (same-fs atomic). Failed unlinks are logged orphans, not client errors.
- `src/modules/api-keys/` — keyStorage. Tokens `buns3_` + 32 bytes base64url; SHA-256 hex digest stored (never the token; hash never leaves the server); `toApiKey` mapping allowlists fields and converts 0/1→boolean (SQLite target has NO boolean codec — capability columns are Int). verify = format regex → hash → single find-and-touch UPDATE (also stamps lastUsedAt). `getAll` (unfiltered, mapped — never leaks hashes), `delete(id)` (null-from-ORM → API_KEY_NOT_FOUND 404). **Keys are immutable** — no update op, ever; rotation = mint new + delete old (decided).
- `src/modules/http/` — Elysia shell. `server.ts` is a composition root only (error handler, openapi, `.use()` per route file, listen — plus the one deliberate exception: the inline `GET /` healthcheck, a one-liner that would be ceremony in its own route file); routes live in `routes/*.routes.ts`, one file per resource, each a named plugin (`routes:*`; macros in `middleware.ts` are `middleware:*`) that `.use()`s the macros it needs (dedupe by name makes this free). Handlers `unwrap()` storage results into throws; central error rendering. Auth guards are declared ONCE per scope: group-level where a group exists (`/keys`), per-route otherwise — no redundant doubling.
- Bucket rows never hit the wire raw: `storage/mapping.ts` (`toBucket`/`toBucketWithCount`) allowlists fields and booleanizes `publicRead` — same lesson as `toApiKey`.
- `src/modules/auth/` — framework-free auth logic, results-as-values: `resolveCredentials(authorization, query)` → `Credentials` (bearer | presign | anonymous; both-presented or malformed presign params → INVALID_API_KEY), `authorize({state, capability, bucket, key, method})` dispatches on `AuthState` (key | presign | anonymous) to per-kind guards. The Elysia macro is a thin adapter over these — do NOT reinline logic into it.
- `src/lib/presign.ts` — pure HMAC presign core: `canonicalString` (`buns3-presign-v1\n` + method\bucket\key\expires, newline-delimited — collision-safe ONLY because bucket/key validators exclude control chars), `sign`/`verify` (HMAC-SHA256 keyed by the stored tokenHash hex string; constant-time compare behind a strict 64-hex regex gate — `Buffer.from(hex)` truncates silently and `timingSafeEqual` throws on length mismatch), `deriveKeyId` (HMAC over a keyid domain string — public fingerprint, NEVER a secret), `buildPresignedUrl` (sign the RAW key, encode via `uriEncodedKey` — the same strictEncode-per-segment the PUT Location header uses, so every object has ONE URL spelling; plain string assembly, never `new URL()` — it normalizes dot-segments and discards any base path; base must be an ORIGIN). Clock and hash injected; no throws. Shared by CLI + API endpoint — never duplicate the URL assembly.
- `src/modules/validation/` — arktype schemas. `CreateApiKey` is a discriminated union: global admin (isAdmin true, bucketName null, canRead/canWrite false) | bucket data key (isAdmin false, bucketName required, ≥1 of read/write via narrow). Bucket names: `^[a-z][a-z0-9-]*$` ≤20 — can't start with `_`, which structurally reserves the whole `_`-prefix namespace for non-bucket routes: `_admin`, `_self`, `_openapi` all live there, and ANY new top-level (non-data) route MUST take a `_` prefix or it can be shadowed by / collide with a valid bucket name (e.g. `openapi` is a valid bucket — see b355f07). **One deliberate exception: `GET /favicon.ico` → 204.** Browsers request that exact path, and it otherwise matches `/:bucket` and 422s on the bucket-name pattern (noise on every page view of the tester pages). Safe because `favicon.ico` contains a dot, so it can NEVER be a valid bucket name and cannot shadow one — the exception is structural, not convenience, and does not generalise to other un-prefixed root routes. Keys: any non-control chars ≤1024, not slash-only, no `.`/`..` path segments (unaddressable via URL path).

## Auth model

- Independent capabilities (no hierarchy): canRead, canWrite, isAdmin. **Admin = control plane only** (cannot read/write objects; mints itself a data key when needed). Data keys are always bucket-scoped; admin keys always global. write does NOT imply read.
- Elysia macro `auth: (capability?: "read"|"write"|"admin"|true)` — `true` = any valid key (whoami). derive resolves credentials → `AuthState` (bucket-blind: bearer verifies now, presign defers); beforeHandle calls `authorize` (bucket-aware: presign sig verification, capability + scope). This split is load-bearing: derives run before beforeHandles, guaranteeing bucketKey validation (422) precedes auth judgments — presign sigs are computed over bucket+key, so verification MUST stay in beforeHandle. Scope mismatch → 403 API_KEY_SCOPE_MISMATCH without consulting bucket existence (S3-style, no existence oracle). whoami reads `authState` (narrows kind === "key"). Key-auth codes are the `API_KEY_*` family (renamed fc6289d — unprefixed `KEY_*` collided with object-land's KEY_NOT_FOUND).
- **Presigned URLs** (query params `keyId`/`expires`/`sig`): offline-signable — sig = HMAC-SHA256(sha256(token), method|bucket|key|expires), keyId derived from the hash client-side, zero schema changes, revocation = delete the key. Any presign param present → presign path (all three must validate; partial/malformed → 401 — never falls back to anonymous). Both header AND params → 401 (ambiguity rejected). Expired → 401 PRESIGNED_EXPIRED (own code group); every other failure collapses to 401 INVALID_API_KEY (no oracle). Verified signer becomes an ordinary principal through the same authorizeKey guards: wrong-bucket signer → 403 API_KEY_SCOPE_MISMATCH, admin signer → 403 API_KEY_NOT_CAPABLE. Data-plane only (no bucket/key on route → 401). Expiry inclusive (`now <= expires`, unix seconds), **TTL capped at 7 days** (604800, S3 parity — RE-decided from "no cap": presigned URLs are unrevocable-except-by-key-deletion grants, the cap bounds leaked-link exposure; longer needs = mint a scoped key), Content-Type unsigned (decided). **ttl is a DURATION; expires is an ABSOLUTE timestamp whose bound (999999999999) is a format check** — one number must never serve both (this drifted 3× in one evening; now pinned by the mint/verify bound-invariant tests). keyId lookup = O(n) scan in verifyPresigned (indexed derived column is the upgrade path). DB-leak trade documented: stored hashes become forge-capable for presign (not for bearer).
- **`POST /_self/presign`** (977bae6): a key presigns FOR ITSELF — body `{method, bucket, key, ttl}` → `{url}`. Capability check = `authorize` with `methodCapabilityMap[method]` (GET/HEAD→read, PUT/DELETE→write; `satisfies`-total over PRESIGN_METHODS) — a key can only presign what it could do itself, so admin keys structurally can't presign (403 API_KEY_NOT_CAPABLE) and wrong-bucket → 403 API_KEY_SCOPE_MISMATCH. Signing happens INSIDE apiKeyStorage.presign (hash never leaves the module; row-gone → INVALID_API_KEY — the caller's own credential died). Presigned creds can't call it (no bucket/key on route → 401): URLs can't mint URLs. Admin tester's Presign section is wired to it (own data-key field).
- 401 (INVALID_API_KEY, with WWW-Authenticate: Bearer) = missing/malformed/unknown credentials; 403 = authenticated but insufficient. Bearer scheme required, case-insensitive prefix.
- **Public-read buckets** (`publicRead`, deny by default, toggled via `PATCH /_admin/buckets/:name`): the anonymous fallback fires ONLY when no Authorization header is present at all, and only for capability "read". Presented-but-invalid credentials → 401 even on a public bucket (S3 semantics). Anonymous on private and nonexistent buckets both → uniform 401 (no existence oracle — the fallback's bucket lookup must not unwrap). **A presented key is always judged as that key**: admin or wrong-bucket data keys get 403 on a public bucket while anonymous gets 200 — deliberate divergence from S3 (credentials opt you into evaluation; drop the header to read publicly).
- Bootstrap: `bun scripts/create-key.ts --name X [--bucket B] [--read] [--write] [--admin]` — prints token ONCE. `/_admin/keys` POST is admin-gated; key zero comes from the script.

## Error handling

- Storage returns `{success, code}` results; HTTP throws `Buns3Error(code)` (via `unwrap`) or `Buns3ValidationError(arkErrors)`.
- `http/error.ts`: `ERROR_STATUS` table `satisfies Record<Buns3AnyErrorCode, number>` (compiler-enforced totality — adding a code without a status breaks the build). Per-class `.error()` registrations render problem+json (RFC 9457) with `code` as extension member; validation errors carry arktype `summary` in `detail`. 500s: generic detail + correlation ref, full error logged server-side. Fallback registration must never throw.
- SQL error translation via structural guards in storage/errors.ts: `isUniqueViolation` (sqlState 23505), `isFkViolation` (23503). SQLite never names FK constraints (`constraint: undefined`) — one Restrict-FK per operation context max, disambiguate by context not constraint.

## Elysia 2.0 gotchas (all learned the hard way)

- Streaming routes need `parse: 'none'` — the parser consumes recognized content-types even without a body schema. Raw stream: destructure `{ request }`, use `request.body`. Never declare body schemas on streaming routes.
- **Params arrive pre-decoded** — do NOT decodeURIComponent again (double-decode aliases keys with literal %).
- `ctx.params` is **undefined** on param-less routes (types claim otherwise) — use `params?.`.
- Wildcard `/:bucket/*` also matches single-segment paths (`/foo` → empty key → NotFound thrown).
- Macros: options-before-handler arg order works; `beforeHandle` isn't suggested by autocomplete but type-checks; macro's own derive output isn't typed in its beforeHandle ctx (annotate the destructured param) — but IS typed correctly in route handler ctx. Macro options at GROUP level (`.group("/keys", { auth: "admin" }, ...)`) guard all children — verified on the wire; don't duplicate per-route.
- Bare `Context` in a hand-typed hook annotation re-asserts `params` as REQUIRED (the params lie, type-approved) — intersect via `Omit<Context, "params">` and re-declare `params?:` optional.
- Repeated query params are last-wins strings (`?sig=a&sig=b` → `"b"`), never arrays; empty value → `""`, absent → undefined. `Record<string, string | undefined>` is wire-true (probed).
- **Macro derive order = the route's OPTIONS-OBJECT KEY ORDER, not plugin registration order** (probed: `{a, b}` runs A's derive first, `{b, a}` runs B's). Anything that must precede auth (bucket/key validation → 422) therefore lives in the macro's `transform` hook, which runs before every derive regardless of ordering; the derive only reads back the validated params for typing. `resolve` no longer exists on macros in 2.0 (merged into derive) — transform is the only earlier phase.
- A macro derive returning a UNION of shapes (`{apiKey: null} | {apiKey: ApiKey}`) poisons the context merge — downstream `params` collapse to `never`/`undefined` in unrelated routes. Return one shape typed `ApiKey | null`.
- Returning BunFile gets free HTTP range support (206). Don't set Content-Length on GET (framework computes, range-aware); DO set it manually on HEAD from object.size, and return a raw `new Response(null, {headers})` (returning `{}` serializes to 2-byte body).
- Elysia auto-strips bodies on HEAD responses — no isHead special-casing needed in error handlers.
- Schema-slot validation loses Standard Schema (arktype) issue messages (beta bug) — admin routes validate MANUALLY in handlers (`CreateApiKey(body)` → throw Buns3ValidationError). Revisit when fixed upstream.
- openapi plugin: RegExp excludes are silently broken (`includes()` not `.test()`) — use exact Elysia route strings; data plane is excluded (wildcards inexpressible in OpenAPI). Docs at **`/_openapi`** (b355f07 — moved off `/openapi` because that IS a valid bucket name and the static route shadowed a bucket named "openapi"; the `_` prefix makes collision structurally impossible), admin plane only, Bearer scheme configured.

## Wire contract highlights

- PUT object: 201 + percent-encoded relative `Location`; overwrites also 201. Empty body allowed (zero-byte objects, S3-style). Content-Type stored verbatim from header (default application/octet-stream, no sniffing — sniffing was deliberately rejected). Max body 5GB (`serve.maxRequestBodySize`).
- GET: metadata-driven headers (stored content-type, Last-Modified UTC, RFC5987 Content-Disposition inline with encoded filename, quoted ETag = blob id). HEAD mirrors GET minus framework-computed headers. **HEAD exists ONLY on the object route** (decided): it's the one endpoint where the body is expensive; admin/self/listing are cheap JSON — use GET. Elysia does NOT auto-map HEAD→GET (probed: GET-only routes answer 404, or 422 via the wildcard for `_`-paths), so a HEAD route exists exactly where typed. The former admin bucket HEADs (one of which was the audit's unauthenticated route) are deleted, along with both storage `head()` methods (`fileStorage.head` was dead AND diverged from `get` on orphans — HEAD must agree with GET on 404, so the object HEAD route uses `get()` and pays the stat).
- DELETE object/bucket: 204; missing → 404 (deliberate, not S3's idempotent 204). Bucket delete refuses non-empty (409 BUCKET_NOT_EMPTY, count pre-check + FK backstop) and removes the empty dir best-effort.
- Keys are defined AFTER percent-decoding; clients must encode. Validation precedes auth (422 before 401/403 — S3 does the reverse; documented trade for lifecycle-ordering robustness). As of 2b44edb this holds on the ADMIN plane too (`useBucket` macro; param renamed `:name`→`:bucket` — wire-invisible): malformed bucket names 422 before auth everywhere.
- **Batch delete `DELETE /:bucket`** with JSON body `{keys: [1..1000 Keys]}` (`auth: "write"`): NO body / empty keys → 422 — absence of keys NEVER means "all keys". Duplicates deduped silently. Per-key results in request order (`{success,key}` | `{success:false,key,code:"KEY_NOT_FOUND"}`) + `{deleted,missing}` summary — missing keys are reported, never batch-failing (race-proof teardown, non-idempotency stays honest). Delete-by-ID from a pre-select ("delete the versions I saw" — concurrent overwrites survive; deliberate), results built from `.deleteAll()`'s RETURNING rows, then best-effort unlinks of exactly those ids (orphans logged, never client errors). Single statement = atomic pointer phase, no explicit tx. Presign structurally can't batch (one key per canonical string). Teardown story: list → batch delete → `DELETE /_admin/buckets/:bucket`.
- **Object listing `GET /:bucket`** (`auth: "list"` — maps to canRead for keys, structurally never anonymous: public-read grants object GET, NEVER enumeration): keyset pagination `?after=<key>&limit=1..1000` (default 100; fetch limit+1, `nextAfter` = last returned key ONLY when the extra row exists — else null), `?prefix=` via code-point range (`key >= prefix AND key < prefixUpperBound(prefix)` in `lib/key.ts`) — NEVER `.like` (SQLite LIKE is ASCII-case-insensitive and `%`/`_` are metachars; keys like `100%.txt` are fixtures). Response `{bucket, filters (effective), count, nextAfter, objects}` via `toObjectSummary` (etag = blob id). Single-segment GETs (`/foo`) now hit this route → 401, not the wildcard's 404 (deliberate wire change). Presigned URLs can't list (no object key on the route). openapi excludes `"/:bucket"` AND `"/:bucket/*"`.

3. ~~**`Cache-Control` on object responses**~~ **DONE 2026-09-04** (`7f1e87b`, `c6320e8`) — found in production: buns3 sent no `Cache-Control`, so Cloudflare invented a 4h default and **flipping a bucket private did NOT stop the object being served** (edge answered 200 while a cache-busted request got 401); the same applied to DELETE, and a presigned URL could outlive its expiry since the signature is never re-checked. Fixed by keying the directive on **how the request was authorized**: `authState.kind` is an exact proxy for cacheability, because anonymous access only ever succeeds on a public-read bucket — no bucket lookup needed. anonymous → `public, max-age=60`; key/presign → `private, no-store` (so a PUBLIC bucket read WITH a key is still private, consistent with "a presented key is always judged as that key" and with HTTP's own rule about authenticated responses). The map is a table that `satisfies Record<AuthKind, string>` rather than a switch with a `default:`, so a fourth AuthKind is a compile error instead of a silent fall-through to `public` — verified by adding one. `Vary: Authorization` on every object response. 60s is short because **keys are MUTABLE** — max-age is exactly how long an overwrite stays invisible.
   - **Conditional requests came with it.** Chrome revalidates the top-level document on EVERY reload (`Cache-Control: max-age=0` + `If-None-Match`), and buns3 answered 200 + full body — an 11.5 kB page cost 11.5 kB per refresh. Now 0.2 kB (measured in the browser; three states confirmed: navigation within 60s = `(disk cache)` no request, reload = 304, changed ETag = 200). `etagMatches` is a pure function in `lib/` because the comparison is fiddly: RFC 9110 **weak** comparison for GET/HEAD (`W/"x"` matches `"x"`), comma-separated lists, and `*`. Stripping `W/` from the whole header instead of per entry made every list member after the first unmatchable — pinned by a test, and both that and the regex anchoring are mutation-checked.
   - `applyObjectHeaders` split into `applyValidatorHeaders` (ETag, Last-Modified, Cache-Control, Vary — sent on BOTH 200 and 304) and `applyPayloadHeaders` (Content-Type, Content-Disposition, and HEAD's Content-Length — only with a body), because **a 304 must not carry representation headers**. Auth stays first: a 304 is a statement about content the caller is entitled to.
   - **`createServer` is now split from `initServer`** (`6594afc`) — the former builds the app, the latter listens. `createServer().handle(new Request(...))` exercises routes, macros, auth and error rendering **in-process with no port** (verified). This is the seam that route-level tier-2 tests and the deferred SDK↔server integration tests both needed. `initServer` was `async` but never awaited anything — Elysia's `.listen()` is synchronous.
   - **Route-level tests** (`__tests__/caching.routes.test.ts`, 18 tests) close this out: directives per auth kind, HEAD agreeing with GET, listings/errors stating nothing (fail-closed), 304 on match, 200 on a stale validator, an overwrite invalidating an old one, `no-store` preserved on an authenticated 304, a 304 NOT bypassing auth, and the favicon route. Mutation-checked (cache leak → 3 failures, no 304 branch → 4, payload-before-conditional → 1). Cloudflare is back to "Eligible for cache" with Edge TTL following the origin header, so public objects cache at the edge and everything else bypasses.
4. **Multipart uploads** — the stated END GOAL (2026-09-04). Immediate motivation: Cloudflare caps REQUEST bodies at 100 MB (Free/Pro; 200 MB Business), so the 5 GB `maxRequestBodySize` is unreachable while proxied — a >100 MB PUT dies at the edge with an HTML 413, which the SDK surfaces as `status: 413, code: "UNKNOWN"` (exactly the proxy-answered case `fromProblem` degrades on). Downloads are unaffected: an 18.4 MB object served fine, and response size is not capped. Beyond the proxy, multipart buys resumability and parallel uploads. **Design questions to settle BEFORE code**: (a) S3's actual API (initiate / upload-part / complete-with-manifest / abort, per-part ETags) or a simpler append-to-session scheme? The S3 shape only earns its keep if existing S3 clients should work against buns3, which has never been a goal — "S3 is a reference point, not a requirement". (b) New durable state: upload sessions and parts held somewhere until completion, where today every object is one atomic move. (c) The write-order invariant changes shape: parts-durable → assemble → pointer, and assembly must itself be crash-safe. (d) A THIRD garbage class (abandoned uploads) joins stale `.tmp` and orphaned blobs — which makes the cron sweeps a prerequisite, not a parallel task. (e) Presign needs `uploadId`/`partNumber` in the canonical string, or a signature would not cover what is actually being uploaded.
5. **Cron cleanup sweeps** — two garbage classes, both created by existing doctrine: stale `.tmp` files (hard crash mid-upload) and orphaned blobs (the "logged orphans" IOU — diff bucket-dir files against pointer ids, unlink strays). **Both sweeps MUST be age-gated (mtime threshold, ~1h)**: blob-without-pointer is also the legitimate mid-flight state of every upload (blob-before-pointer invariant) — an ungated sweep is a data-eater racing live uploads. Nothing else needs cleanup by construction: presigned URLs are stateless, keys have no TTL. Single-instance = in-process scheduler, no locks. Plugin: check `@elysiajs/cron` dist-tags for a `2.0.0-*` release FIRST (house lesson — latest lies); fall back to bare `croner` or an interval — sweeps are storage-domain functions (tier-2 testable: seed an orphan, assert) with the scheduler as thin wiring. Option to bank: expose the sweep as `POST /_admin/cleanup` too (manual trigger, admin tester button).
6. **Versioning the server itself** — raised 2026-09-04, now that buns3 is deployed. **Current state: nothing identifies a build.** Root `package.json` has NO `version` field, there are no git tags, `GET /` returns only `{"message":"OK"}`, and compose builds images with no explicit tag (so `:latest`). Consequences: **no rollback** (a redeploy cannot return to a known-good image), no way to ask a running server what it is, and no anchor for SDK↔server compatibility (the SDK is at 0.1.0 against an unversioned server). Questions: semver for the server, with a wire-contract change as the breaking trigger? Do the server and `@buns3/sdk` version together or independently with a documented compatibility range (independent is normal, but they ARE coupled by the wire contract — the error-code drift guard already assumes they agree)? Where does the version live, given the root package is `private: true`? Expose it where — `GET /` is unauthenticated, so putting a build identifier there tells the internet what to exploit; `/_admin` or a response header are quieter options. Tag Docker images with the version AND the git sha rather than `latest`, which is what actually buys rollback. Changelog/releases as a separate question.

8. **Object versioning** — parked for thinking (raised 2026-09-04), no commitment. **The existing layout is already most of the way there**: blobs are `data/<bucket>/<uuid>` with the pointer in SQLite, so every write already mints a fresh blob with its own id — the id IS a natural version id, and it is already the ETag. Versioning is essentially "stop deleting the old pointer on overwrite". Batch delete already resolves keys to blob ids first and deletes by id ("delete the versions I saw"), so the vocabulary exists in the code. Questions to settle before anything: is it per-bucket opt-in (S3 has a bucket flag) or global? Does GET take `?versionId=` and default to latest? Does DELETE insert a delete-marker (S3) or actually remove — and how does that interact with the decided "deletes are honest, not idempotent" 404? Does listing show only the latest by default, and is there a separate way to list versions? What happens to `createdAt` semantics, currently documented as "the current version's write time"? Storage grows without bound unless there is expiry, which ties straight into the cron sweeps and would make them a lifecycle engine rather than a garbage collector. And presign would need `versionId` in the canonical string, or a signature would not cover which version is served. **The S3-clone cliff applies here more than anywhere** — version listing, delete markers and lifecycle rules are where S3 gets genuinely complicated, and "simplicity wins" may argue for a much smaller thing (keep N previous versions, restore-by-id, no markers) or for not doing it at all.
